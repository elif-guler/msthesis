#+TITLE: nb_target_check

* Why this check exists

Fur (and most likely Seqwin) only works correctly if the target/neighbor
split is actually correct - if a genome is mislabeled as a neighbor when
it's really closely related to the targets (or vice versa), it can pollute
the results (either hiding real target-unique sequences, or introducing
false ones).

The =acc.txt= tables encode a "first separation" - however Unikseq/Neptune
originally decided what counts as target vs neighbor (likely taxonomy- or
metadata-based, not sequence-based). The idea of this whole project is to
get a second, independent opinion using actual genetic distance
(=phylonium=) and see where the two disagree. Disagreements
(=target_to_neighbor.txt=/=neighbor_to_target.txt=) are exactly the
genomes worth double-checking manually before trusting Unikseq/Neptune's
results.

Once the target/neighbor separation is settled, the next question is
whether =fur= and =seqwin= (two different marker-finding tools) actually
agree on what makes a good target-specific marker - that's what the later
scripts in this log are for.

* Goal

Check whether the target/neighbor genome labels used for Unikseq and
Neptune (given in each dataset's =acc.txt=) actually hold up
phylogenetically, using =phylonium= distances + tree-based clade-finding,
then feed the corrected target/neighbor sets into =fur= and =seqwin= and
compare their marker output.

Datasets: =clo= (C. difficile), =mtb= (M. tuberculosis), =sen= (S. enterica).
Each has two sample pools: =100= and =1000= genomes - these exist because
using every available genome as a neighbor would be far too slow/large to
run through phylonium and the downstream tools, so a manageable subsample
is used instead. Two pool sizes are checked to see whether the answer (does
the separation hold up, do fur/seqwin agree) changes depending on how many
neighbors are considered.

* Scripts

** runpipeline.sh <table.tsv> <outdir> [100|1000]
Reads the table (fixed columns: 1=accession 2=Is target 3=sampled100
4=sampled1000), builds target/neighbor accession lists filtered to the
chosen pool, downloads genomes via NCBI =datasets= (dehydrated + rehydrate,
more resilient to network errors than a single zip stream), flattens each
genome to one FASTA named by accession, then runs =phylonium= on everything,
dropping any genome that produces =nan= distances (too little homology to
compare) and retrying.

/Why fixed columns instead of matching the header text:/ the table has a
comment line before the real header row, which broke a name-based lookup
(see bugs below) - reading by position sidesteps the question of "which
row is the header" entirely.

/Why dehydrate+rehydrate instead of a plain download:/ a single zip
download of thousands of genomes is one long network stream - if it drops
partway through (which it did, on the largest set), the whole thing
fails and restarts from zero. Rehydration downloads files individually, so
a dropped connection only costs you that one file, and rehydrate can be
rerun to pick up just what's missing.

/Why drop nan-distance genomes instead of erroring out:/ phylonium can't
compute a meaningful distance between genomes with almost no shared
sequence - that's not a bug, it just means that genome doesn't belong in
this comparison. Removing it and continuing is more useful than the whole
run failing because of one outlier genome (which, in the mtb set, turned
out to consistently be the same accession across all its pairs - a sign
it's specifically that genome, not the dataset).

** check_separation.sh <table.tsv> <outdir> [100|1000]
Takes the FASTAs from =runpipeline.sh=, copies them into an =all/= dir with
=t=/=n= filename prefixes, builds a tree (=nj= | =midRoot= | =land=), finds
the best-supported target clade with =fintac= + =pickle= (the "second
separation"), diffs it against the table's labels ("first separation"),
and writes =target_to_neighbor.txt=/=neighbor_to_target.txt= for any
disagreement. Also builds =targets/=/=neighbors/= dirs of symlinked FASTAs
from the second separation, matching the layout the reference pipeline
(=~/ch_mapro/mapro/3taxa=) uses for =fur=/=seqwin=.

/Why t/n-prefix the filenames:/ =fintac= and =pickle= need some way to know
which tips in the tree started out labeled target vs neighbor, so they can
score candidate clades by how well they match that original labeling. The
prefix is how that information rides along inside the tree file itself.

/Why symlinks instead of copies for targets/neighbors:/ the same genome
FASTA already exists once in =fastas/= and again (prefixed) in =all/= -
copying a third time would triple the disk use for no benefit, since
=fur=/=seqwin= just need to read the sequence, not own a private copy of
it.

** runall.sh [100|1000] [dataset ...]
Runs =runpipeline.sh= then =check_separation.sh= for each dataset, writing
into =<dataset>/pool_100/= or =<dataset>/pool_1000/=. Keeps going if one
dataset fails.

/Why separate pool_100/pool_1000 subdirectories:/ without this, rerunning
with =1000= after already having =100= results would silently overwrite
them (same filenames, same dataset dir) - splitting by pool means both
sample sizes' results can be compared side by side afterward.

/Why keep going instead of stopping on the first failure:/ the three
datasets are independent - one dataset having a bad genome or a network
hiccup shouldn't block you from seeing results for the other two the same
day.

** run_fur_seqwin.sh
Runs =makeFurDb= -> =fur= -> =seqwin= on the =targets/=/=neighbors/= dirs,
for every dataset x pool combination. Skips any combination missing
=targets/=/=neighbors/= (i.e. =check_separation.sh= hasn't been run for it
yet). Keeps going if one combination fails. Writes =markers.fasta= (fur)
and =seqwin-out/signatures.fasta= (seqwin) per pool.

** analyze_cons.py <signatures.fasta> <targets_dir> <neighbors_dir> <output.csv> [genome_ext]
For one marker set (fur's or seqwin's), BLASTs every marker against every
target and every neighbor genome, and reports per marker: conservation (how
identical it is across targets), divergence (how different from
neighbors), and the fraction of neighbors it still hits at all.

/Why =-evalue 1e-5= was added:/ without an e-value cutoff, almost every
marker hit almost every neighbor genome somewhere (fraction_nontarget_hit
close to 1 for nearly everything), because BLAST was counting very weak,
essentially spurious alignments as "hits". Restricting to e-value <= 1e-5
only counts hits unlikely to occur by chance, which is what
"fraction_nontarget_hit" is actually supposed to measure.

** run_cons.sh
Runs =analyze_cons.py= twice per pool (fur's =markers.fasta=, seqwin's
=signatures.fasta=), for all 6 dataset/pool combinations. Writes
=cons_div_fur.csv= / =cons_div_seqwin.csv= per pool.

** calculate_marker_bp.sh
Sums total basepairs and counts markers in =markers.fasta= and
=signatures.fasta= for every dataset/pool. Writes one combined
=marker_bp_summary.csv=.

** blast_markers.py
Deliberately kept very simple - no command-line arguments, just three
paths to edit at the top (=markers.fasta=, =seqwin-out/signatures.fasta=,
output csv). BLASTs fur's markers as query against seqwin's markers as
subject, and for each fur marker keeps the longest hit. A marker counts as
"found" in seqwin's set if that hit is >=95% identity and >=90% of the
marker's length (both thresholds editable at the top of the script) - this
is the check for whether fur's markers are a subset of seqwin's.

** markers_blast.sh
Runs =blast_markers.py= for all 6 dataset/pool combinations, by =cd=-ing
into each pool folder first (since the script itself takes no arguments).
Writes a combined =fur_subset_summary.csv=.

** plot_grid.R
Reads all 12 =cons_div_fur.csv=/=cons_div_seqwin.csv= files and plots
fraction-of-neighbors-hit (x) vs divergence (y) in a 2x6 grid: rows =
seqwin/fur, columns = the 3 taxa under pool_100 (left) then pool_1000
(right). Writes =cons_div_grid.png=.

** plot_marker.R
Reads =marker_bp_summary.csv= and plots total marker basepairs as bars,
grouped by tool (fur/seqwin), faceted by pool and taxon with independent
y-scales per panel. Writes =marker_bp_histogram.png=.

/Why independent y-scales per panel:/ marker counts/basepairs vary by
orders of magnitude between pools (e.g. clo pool_1000 fur has 4 markers,
mtb pool_100 seqwin has 1674) - on one shared y-axis the small bars are
invisible next to the large ones.

* Bugs found and fixed along the way

- *Scripts need =chmod +x=* - "Permission denied" when calling
  =./script.sh= directly. Running with =bash script.sh= works regardless of
  permissions because bash reads the file as a script either way, but
  =runall.sh='s internal =./runpipeline.sh= calls invoke it as an
  executable, which needs the execute bit set on the file itself.

- *Big =datasets download= zips failed mid-stream* on large sets (mtb, 7679
  genomes) with an HTTP2 =INTERNAL_ERROR=. This is a transient
  network/server hiccup, more likely to hit on a long single download than
  on many short ones. Fixed by switching to =--dehydrated= + =datasets
  rehydrate=, which fetches files individually and can be rerun to pick up
  only what's missing, rather than restarting one giant stream from zero.

- *=phylonium= dies on genomes with <20% homology* to the rest of the set
  (=nan= distances) - one bad/unrelated genome poisons the whole distance
  matrix, and with =set -e= that killed the entire script. The fix loops:
  find whichever genome has the most =nan= distances, move it out, retry -
  this treats "can't be compared" as a data-quality signal about that one
  genome rather than a fatal script error.

- *=acc.txt= actually has two non-data rows* (a comment line, then the real
  header), not one. The original approach searched row 1 for the column
  name and never found it, because row 1 was the comment, not the header -
  so the neighbor filter silently matched nothing (an unset column index in
  awk defaults to referring to the whole line, which never equals
  "TRUE"/"FALSE"). Fixed by reading columns by fixed position instead of by
  name - this doesn't care which row is the header, or whether there's a
  comment row at all.

- *Target list wasn't filtered by the sample-pool column* - it pulled in
  all ~3328 rows labeled target regardless of pool, while neighbors were
  correctly filtered down to the ~20-80 meant for that pool. The two lists
  are supposed to describe the same subsampled set (e.g. "the 100-genome
  pool"), so both need the identical filter condition, not just one of
  them.

- *=check_separation.sh= got overwritten with pasted terminal output* by
  accident (a copy/paste landed in the wrong window) - not a logic bug,
  just a reminder that pasting into a script file silently replaces its
  contents with no diff shown, so it's worth a quick =head= after any paste
  into an existing file.

- *Rerunning with =1000= would have overwritten the =100= results*, since
  both wrote straight into the dataset directory using the same filenames.
  Splitting into =pool_100=/=pool_1000= subdirectories fixes this by giving
  each sample size its own namespace, so nothing needs to be manually
  backed up before switching pools.

- *=runpipeline.sh= downloads are multi-GB per dataset/pool*
  (=genomes/=, =fastas/=, =all/=, =genomes.zip=, =*.phy=, =phylonium.log=).
  These are all regenerable by rerunning the pipeline, and GitHub both
  discourages and hard-blocks large files - so they're excluded via
  =.gitignore=. The same turned out to be true of =target.db/= (fur's
  database, which duplicates the target genomes again) and
  =seqwin-out/blastdb/=/=seqwin-out/sketches.msh= - all added to
  =.gitignore= once they showed up in a =git add -n .= dry run.

- *=grep -c= "double zero" bug*, twice, in different scripts. =grep -c
  '^>' file= prints =0= when there are no matches, but still exits with
  status 1 (because it found nothing) - so any =grep -c ... || echo 0=
  fallback runs *in addition to* the real =0= that was already printed,
  producing two lines instead of one. This first showed up as duplicated
  "0" output in =run_fur_seqwin.sh='s marker-count logging, then again in
  =calculate_marker_bp.sh= where it corrupted a CSV row into two malformed
  ones (showing up as unexplained =NA= values downstream in R). Fixed both
  by capturing =grep='s output directly and defaulting to 0 only if the
  output was actually empty, instead of relying on its exit status.

- *=fraction_nontarget_hit= was close to 1 for almost every marker* in
  =analyze_cons.py= - BLAST was counting very weak, low-significance
  alignments as hits. Fixed by adding =-evalue 1e-5= to the =blastn= call.
